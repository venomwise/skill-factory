# Dispatch Contract

工作包派发模式的分派契约。主代理按本契约向实现子代理下发工作包并接收报告；
分包规则和验证关卡以 `SKILL.md` 的 *Work package dispatch mode* 为准。

本契约不绑定具体运行时的工具名；任何满足「启动实现代理并接收文本报告」的机制都适用，
没有该机制的运行时使用默认主线程模式。

## Dispatch instruction

每个工作包的分派指令包含：

1. 包编号和任务清单：包内每个任务的编号、完整文本和 `_Acceptance:` / `_Design:` 元数据。
2. 引用的 AC 原文：从 `design.md` 摘录本包涉及的 Acceptance Criteria，注明出处章节。
3. 适用的 Implementation Contract 条目：只包含本包改动路径适用的约束及其验证方法，
   不复制整份仓库指导。
4. 执行基线：开始时的分支或提交、既有用户改动、本包声明的文件集。
5. `design.md` 和 `tasks.md` 的路径：子代理只读 `design.md`；不读取也不修改 `tasks.md`。
6. 报告格式：见下节。

分派指令不得包含「遇到模糊处自行决定」的授权；任务文本、引用和契约之外的行为
属于设计缺口，必须在报告中交回主代理。

## Sub-agent rules

- 按任务清单的原顺序逐个实现；每完成一个任务执行任务级验证再进入下一个。
- 改动范围以本包声明的文件集为界；确需触碰包外文件时停止扩展，在报告中说明。
- 可以修改实现代码和测试；不得修改 `design.md`、`tasks.md`、checkbox 状态或
  其他工作包的产物。
- 不引入任务范围外的行为、重构或依赖；不为凑验证编写无断言的测试。
- 遇到设计缺口、AC 冲突、破坏性操作或缺少依赖时停止，并在报告中说明，
  不自行绕过或降级处理。

## Report format

子代理按包返回一份报告：

- **Package**: <包编号和任务清单>
- **Per task**: 任务编号、完成或停止、改动的文件列表。
- **Evidence**: 执行的验证命令、关键输出摘要、每条引用 AC 的核对结果。
- **Out-of-package changes**: 无，或必须触碰包外文件的原因。
- **Open items**: 设计缺口、需要用户决策的事项、未解决的失败。

报告是验证输入，不是完成证据；主代理依据实际 diff 独立复核。

## Retry and takeover

1. 验证失败时，主代理把具体缺口（失败命令、未满足的 AC、违反的 Contract 条目）
   反馈给子代理，重做一次；重试只允许一次。
2. 重试仍失败、子代理报告无法继续，或报告与承诺范围不符时，主代理接管该包
   在主线程完成，或按 *Blocker escalation* 报告。
3. 接管或报告前，未完成的任务保持 `[ ]`，不标记任何部分完成的进度。
