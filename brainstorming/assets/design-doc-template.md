# <Topic> Design

## Summary

一段话说明我们在构建什么以及为什么。

## Goals

- 主要成果和可衡量的成功指标。

## Primary Users / Roles

- 谁使用这个以及他们的关键目标。

## Non-Goals

- 明确的范围外内容，以防止范围蔓延。

## Context

- 相关的现有行为、约束和相关模块。

## Discovery (recommended for non-trivial or ambiguous requirements)

### Key Discoveries

- 在 brainstorming 期间测试的值得注意的假设和浮现的盲点。

### Scope Decisions

- 明确包含和排除的内容及其理由。

## Decision Record

捕获权衡过的替代方案以及为什么选择的方案获胜，以便以后可以重新审视该决策。记录在 brainstorming 期间实际比较的选项；do not invent 从未摆上台面的替代方案。

### Options Considered

- 每个评估过的方案一个条目，每个都有其关键权衡（pros, cons, cost, risk）。If only 一个方案可行，在此说明。

### Decision & Rationale

- 选定的方案以及它胜过其他方案的具体原因。If only 一个方案可行，记录为什么替代方案被排除。Note 用户明确做出的任何决策或强制选择的约束。

## Proposed Solution

高层方法以及它为什么适合约束。

### Architecture

关键构建块及其关系。

### Components

列出组件及其职责和接口。

### Data Flow

主路径的逐步流程。

## Error Handling

主要失败模式以及如何处理它们。

## Testing

关键测试用例以及它们在哪里运行。

## Open Questions

Only 在 discovery 期间已浮现的未解决问题。If none remain，write: "None. Key decisions were confirmed during discovery."
