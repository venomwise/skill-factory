## 1. 背景
需要一个用户管理系统支持内部员工管理。

---

## 2. 功能需求

### 2.1 用户列表
- 显示所有用户（根据当前登录用户权限过滤）
- 支持按姓名、邮箱搜索
- 支持按角色、状态筛选
- 分页展示，每页20条

### 2.2 用户详情
- 查看用户基本信息（姓名、邮箱、角色、状态、创建时间）
- 查看用户权限清单
- 权限要求：所有登录用户可查看

### 2.3 用户编辑
- 管理员可以编辑用户信息
- 管理员可以分配权限
- **编辑权限边界:**
  - 超级管理员可以编辑所有用户（包括自己和其他超级管理员）
  - 普通管理员可以编辑普通用户和观察者，不能编辑任何管理员（包括自己）
  - 可编辑字段：姓名、邮箱、角色、状态
  - 不可编辑字段：用户ID、创建时间

### 2.4 用户创建
- 管理员可以创建新用户
- 必填字段：姓名、邮箱、角色
- 创建时默认状态为"待激活"

### 2.5 用户删除
- 超级管理员可以删除用户（除了自己）
- 删除时需二次确认
- 删除后该用户创建的业务数据保留，创建人显示为"已删除用户"

## 3. 权限模型

### 3.1 角色定义

| 角色代码 | 角色名称 | 说明 |
|---------|---------|------|
| `super_admin` | 超级管理员 | 系统最高权限，可管理所有用户和数据 |
| `admin` | 普通管理员 | 可管理普通用户和观察者 |
| `user` | 普通用户 | 只能查看用户列表和详情 |
| `observer` | 观察者 | 只能查看用户列表，不能查看详情 |

### 3.2 权限矩阵

| 功能 | 超级管理员 | 普通管理员 | 普通用户 | 观察者 |
|-----|-----------|-----------|---------|--------|
| 查看用户列表 | ✓ | ✓ | ✓ | ✓ |
| 查看用户详情 | ✓ | ✓ | ✓ | ✗ |
| 创建用户 | ✓ | ✓ | ✗ | ✗ |
| 编辑超级管理员 | ✓ | ✗ | ✗ | ✗ |
| 编辑普通管理员 | ✓ | ✗ | ✗ | ✗ |
| 编辑普通用户/观察者 | ✓ | ✓ | ✗ | ✗ |
| 删除用户 | ✓（不能删除自己） | ✗ | ✗ | ✗ |
| 分配权限 | ✓ | ✓（仅限普通用户和观察者） | ✗ | ✗ |

### 3.3 权限粒度
- **功能级权限：** 控制能否访问特定功能（增删改查）
- **数据级权限：** 控制能看到哪些用户数据（基于角色层级）

## 4. 数据模型

### 4.1 用户表 (t_user)

| 字段名 | 数据类型 | 约束 | 说明 | 示例值 |
|-------|---------|------|------|--------|
| id | BIGINT | PRIMARY KEY, AUTO_INCREMENT | 用户ID | 10001 |
| name | VARCHAR(50) | NOT NULL | 姓名 | 张三 |
| email | VARCHAR(100) | NOT NULL, UNIQUE | 邮箱（唯一，用于登录） | zhangsan@example.com |
| role | VARCHAR(20) | NOT NULL | 角色代码，枚举值见下方 | admin |
| status | TINYINT | NOT NULL, DEFAULT 0 | 用户状态，枚举值见下方 | 1 |
| created_at | DATETIME | NOT NULL, DEFAULT CURRENT_TIMESTAMP | 创建时间 | 2026-07-01 10:30:00 |
| updated_at | DATETIME | NOT NULL, DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP | 更新时间 | 2026-07-01 10:30:00 |

#### 4.1.1 role 字段枚举值

| 值 | 含义 |
|----|------|
| `super_admin` | 超级管理员 |
| `admin` | 普通管理员 |
| `user` | 普通用户 |
| `observer` | 观察者 |

#### 4.1.2 status 字段枚举值

| 值 | 含义 | 说明 |
|----|------|------|
| 0 | 待激活 | 新创建用户的默认状态，需要用户首次登录激活 |
| 1 | 正常 | 可正常使用系统 |
| 2 | 已禁用 | 管理员手动禁用，无法登录 |

#### 4.1.3 状态流转规则

```
待激活(0) --[用户首次登录]--> 正常(1)
正常(1) --[管理员禁用]--> 已禁用(2)
已禁用(2) --[管理员启用]--> 正常(1)
```

## 5. 异常场景处理

### 5.1 邮箱重复
- **场景:** 创建或编辑用户时，邮箱与现有用户重复
- **处理:** 
  - 提示："该邮箱已被使用，请使用其他邮箱"
  - HTTP状态码：400 Bad Request
  - 错误代码：USER_EMAIL_DUPLICATE

### 5.2 删除用户后的数据处理
- **场景:** 删除用户后，该用户创建的业务数据如何处理
- **处理:**
  - 用户记录软删除（is_deleted=1），不物理删除
  - 业务数据保留，创建人字段保持原值
  - 前端显示时，若创建人已删除，显示"已删除用户"
  - 删除的用户不再出现在用户列表中

### 5.3 并发编辑冲突
- **场景:** 多个管理员同时编辑同一个用户
- **处理:**
  - 使用乐观锁机制（updated_at作为版本号）
  - 后提交的编辑操作检测到updated_at不匹配时
  - 提示："该用户信息已被他人修改，请刷新后重试"
  - HTTP状态码：409 Conflict
  - 错误代码：USER_EDIT_CONFLICT

### 5.4 权限不足
- **场景:** 用户尝试执行无权限的操作
- **处理:**
  - 提示："您没有权限执行此操作"
  - HTTP状态码：403 Forbidden
  - 错误代码：PERMISSION_DENIED

### 5.5 用户不存在
- **场景:** 查询、编辑、删除的用户ID不存在
- **处理:**
  - 提示："用户不存在或已被删除"
  - HTTP状态码：404 Not Found
  - 错误代码：USER_NOT_FOUND

### 5.6 删除最后一个超级管理员
- **场景:** 尝试删除系统中唯一的超级管理员
- **处理:**
  - 禁止删除操作
  - 提示："系统至少需要保留一个超级管理员"
  - HTTP状态码：400 Bad Request
  - 错误代码：LAST_SUPER_ADMIN

## 6. 非功能需求

### 6.1 性能要求
- 支持 1000 并发用户
- 用户列表查询响应时间 < 500ms
- 用户详情查询响应时间 < 200ms

### 6.2 安全要求
- 数据传输使用 HTTPS 加密
- 密码使用 BCrypt 加密存储
- 登录失败5次后锁定账号30分钟
- 操作日志记录所有增删改操作

### 6.3 可用性要求
- 系统可用性 ≥ 99.5%
- 数据备份：每天凌晨3点全量备份
