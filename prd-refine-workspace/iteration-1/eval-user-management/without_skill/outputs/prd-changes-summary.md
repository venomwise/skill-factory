## 二、详细变更内容

### 变更1: 补充完整的权限模型 ✅

**问题来源:** P1-1 权限模型设计不明确

**新增内容:**

#### 1.1 角色定义（第3.1节）
明确定义了4种角色：
- `super_admin` - 超级管理员（系统最高权限）
- `admin` - 普通管理员（可管理普通用户和观察者）
- `user` - 普通用户（只能查看）
- `observer` - 观察者（只能查看列表）

#### 1.2 权限矩阵（第3.2节）
用表格形式清晰列出了每个角色对每个功能的权限：
- 查看用户列表：所有角色
- 查看用户详情：除观察者外
- 创建用户：仅管理员
- 编辑用户：根据角色层级区分
- 删除用户：仅超级管理员
- 分配权限：管理员（有限制）

#### 1.3 权限粒度（第3.3节）
明确两个维度：
- 功能级权限：控制能否访问特定功能
- 数据级权限：控制能看到哪些用户数据

**开发建议:** 建议使用注解或拦截器实现权限控制，可参考 Spring Security 或自研权限框架。

---

### 变更2: 明确数据字段定义 ✅

**问题来源:** P1-2 数据字段定义模糊

**新增内容:**

#### 2.1 用户表完整定义（第4.1节）
补充了详细的字段信息表：

| 字段 | 新增说明 |
|-----|---------|
| email | 明确为 UNIQUE 约束，必填，用于登录 |
| role | 明确为枚举类型，补充了4个可选值及含义 |
| status | 明确为 TINYINT 类型，补充了3个状态值及含义 |
| updated_at | 新增字段，用于乐观锁实现 |

#### 2.2 状态流转规则（第4.1.3节）
补充了状态机图，明确：
- 待激活 → 正常（用户首次登录）
- 正常 ↔ 已禁用（管理员操作）

**开发建议:** 
- 使用枚举类封装 role 和 status 字段
- updated_at 字段使用数据库自动更新机制
- 建议为 email 字段添加索引提升查询性能

---

### 变更3: 明确编辑权限边界 ✅

**问题来源:** P1-3 用户编辑权限边界不清

**新增内容:**

#### 3.1 编辑权限规则（第2.3节）
明确规定：
- **超级管理员：** 可以编辑所有用户（包括自己和其他超级管理员）
- **普通管理员：** 只能编辑普通用户和观察者，不能编辑任何管理员（包括自己）

#### 3.2 字段编辑限制
- **可编辑字段：** 姓名、邮箱、角色、状态
- **不可编辑字段：** 用户ID、创建时间

**开发建议:** 
- 在编辑接口中增加角色层级校验逻辑
- 前端根据当前登录用户角色动态控制编辑按钮的显示
- 后端必须再次校验权限，防止接口绕过

---

### 变更4: 补充异常场景处理 ✅

**问题来源:** P2-4 缺少异常场景说明

**新增内容:**

补充了6种异常场景的处理规则（第5章）：

| 场景 | HTTP状态码 | 错误代码 | 处理方式 |
|-----|-----------|---------|---------|
| 邮箱重复 | 400 | USER_EMAIL_DUPLICATE | 提示用户更换邮箱 |
| 删除用户后的数据处理 | - | - | 软删除用户，业务数据保留 |
| 并发编辑冲突 | 409 | USER_EDIT_CONFLICT | 乐观锁，提示刷新 |
| 权限不足 | 403 | PERMISSION_DENIED | 提示无权限 |
| 用户不存在 | 404 | USER_NOT_FOUND | 提示用户不存在 |
| 删除最后一个超级管理员 | 400 | LAST_SUPER_ADMIN | 禁止删除 |

**开发建议:**
- 实现统一异常处理器，返回标准化错误响应
- 乐观锁使用 updated_at 字段实现
- 删除操作使用软删除（添加 is_deleted 字段）
