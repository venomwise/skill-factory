# 用户管理系统 PRD 评审报告

**评审日期:** 2026/06/25
**评审人:** 技术委员会

## [P0-阻断] 问题

无

## [P1-需确认] 问题

### 1. 权限模型设计不明确

**问题描述:** PRD 中提到"管理员可以分配权限",但未明确:
- 有哪些角色?(只提到了"管理员")
- 每个角色有哪些权限?
- 权限粒度是什么?(功能级?数据级?)

**影响范围:** 核心功能设计

**建议:** 补充完整的权限矩阵,明确角色定义和权限边界

---

### 2. 数据字段定义模糊

**问题描述:** 用户表中的字段定义不够清晰:
- `role` 字段:是枚举还是字符串?有哪些可选值?
- `status` 字段:有哪些状态?状态流转规则?
- `email` 字段:是否唯一?是否必填?

**影响范围:** 数据库设计、业务逻辑

**建议:** 补充字段约束、数据类型、可选值、业务规则

---

### 3. 用户编辑权限边界不清

**问题描述:** "管理员可以编辑用户信息",但:
- 管理员能否编辑自己?
- 管理员能否修改其他管理员?
- 哪些字段可以编辑,哪些不可以?

**影响范围:** 权限控制逻辑

**建议:** 明确编辑权限的边界条件和限制规则

## [P2-优化] 问题

### 4. 缺少异常场景说明

**问题描述:** PRD 未涵盖异常场景:
- 删除用户后,该用户创建的数据如何处理?
- 邮箱重复时如何提示?
- 并发编辑冲突如何解决?

**影响范围:** 产品体验

**建议:** 补充主要异常场景的处理规则
