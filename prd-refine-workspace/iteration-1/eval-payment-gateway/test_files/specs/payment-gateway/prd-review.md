# 支付网关集成 PRD 评审报告

**评审日期:** 2026/06/28
**评审人:** 安全团队 + 架构团队

## [P0-阻断] 问题

### 1. 支付回调幂等性缺失

**问题描述:** PRD 未说明如何保证回调幂等性。支付网关可能重复推送回调,如果不做幂等处理,会导致:
- 订单状态被重复更新
- 重复发放商品/服务
- 资金账户异常

**影响范围:** 核心业务逻辑,资金安全

**建议:** 必须补充幂等性设计方案

---

### 2. 缺少敏感信息加密方案

**问题描述:** PRD 只提到"HTTPS 传输",但未说明:
- 支付参数(金额、订单号)是否需要加密存储?
- 支付密钥如何管理?(不能硬编码在代码中)
- 日志中是否会泄露敏感信息?

**影响范围:** 数据安全,合规风险

**建议:** 补充完整的加密和密钥管理方案

## [P1-需确认] 问题

### 3. 回调超时处理策略不明确

**问题描述:** 如果支付网关回调失败或超时:
- 是否需要主动查询支付状态?
- 多久查询一次?查询多少次?
- 查询失败后如何通知用户?

**影响范围:** 用户体验,订单准确性

**建议:** 补充异常处理和补偿机制

---

### 4. 并发支付冲突未考虑

**问题描述:** 用户可能在短时间内多次点击"支付"按钮:
- 是否会生成多个支付订单?
- 如何防止重复扣款?

**影响范围:** 资金安全,用户体验

**建议:** 补充防重复提交机制

## [P2-优化] 问题

### 5. 缺少监控和告警

**问题描述:** 金融系统需要实时监控:
- 支付成功率下降如何告警?
- 回调失败如何通知?
- 异常交易如何发现?

**建议:** 补充监控指标和告警规则
