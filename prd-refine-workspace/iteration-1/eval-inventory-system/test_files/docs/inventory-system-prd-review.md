# 库存管理系统 PRD 评审报告

**评审日期:** 2026/06/26
**评审人:** 技术团队

## [P0-阻断] 问题

### 1. 高并发下的库存超卖风险

**问题描述:** 当前设计使用数据库字段 `stock` 和 `reserved_stock`,但未说明如何保证并发安全:
- 多个用户同时下单同一商品,如何防止超卖?
- 数据库层面是否使用行锁?乐观锁?悲观锁?
- UPDATE 语句如何保证原子性?

**影响范围:** 核心业务逻辑,可能导致超卖

**建议:** 必须补充并发控制方案

---

### 2. 预占库存的超时释放机制缺失

**问题描述:** PRD 提到"订单超时未支付时回补库存",但:
- 超时时间是多久?
- 如何检测超时订单?(定时任务?消息队列?)
- 如果定时任务故障,预占库存会永久锁死吗?

**影响范围:** 库存准确性,可能导致库存虚高

**建议:** 补充超时释放的完整机制

## [P1-需确认] 问题

### 3. 1000 QPS 的性能目标可行性存疑

**问题描述:** PRD 要求"支持 1000 QPS",但:
- 当前方案是直接操作 MySQL,每次扣减都是一次数据库写操作
- 如果有热门商品(秒杀场景),数据库会成为瓶颈
- 是否需要引入缓存(Redis)来提升性能?

**影响范围:** 系统性能,用户体验

**建议:** 评估性能瓶颈,考虑引入缓存或其他优化方案

---

### 4. 分布式场景下的库存一致性

**问题描述:** 如果应用部署多个实例:
- 如何保证库存扣减的全局一致性?
- 是否需要分布式锁?

**影响范围:** 分布式部署场景下的数据一致性

**建议:** 明确分布式场景下的一致性保证方案

## [P2-优化] 问题

### 5. 缺少库存预警机制

**问题描述:** 库存不足时应该提前预警:
- 库存低于多少时通知运营?
- 如何通知?(邮件?短信?)

**建议:** 补充库存预警规则
